## Команды

```sh
npm ci
npm test
npx playwright install chromium
npm run test:e2e
```

`test:e2e` автоматически собирает сайт и запускает preview на `127.0.0.1:4173`. Порт должен быть свободен. Chromium проверяет ширины **320, 375, 768, 1024, 1440 и 1920 px**, каждую в светлой и тёмной теме. На 320 и 375 px дополнительно включены мобильный режим и сенсорный ввод. Всего 12 конфигураций браузера. При падении сохраняется trace в `test-results/`; его можно открыть командой `npx playwright show-trace <путь-к-trace.zip>`.

Браузерные тесты используют актуальные дисциплины, первую опубликованную статью базы знаний и первое домашнее задание из репозитория. Добавление, переименование или удаление материалов через CMS не требует менять тесты. При отсутствии определённого типа материалов пропускаются только зависимые от него сценарии, с пояснением причины. Независимые компонентные тесты продолжают проверять оба типа материалов и пустые состояния на тестовых данных. Проверка переполнения обходит все страницы контента и страницу ошибки. Снимки этих страниц для всех размеров и тем сохраняются в `tmp/qa/`.

## Ручная приёмка после подключения Pages CMS

Эти проверки требуют учётной записи GitHub и прав на репозиторий. Локальные тесты не подтверждают авторизацию внешнего сервиса.

1. Войти в Pages CMS через GitHub, открыть нужные репозиторий и ветку. Проверить настройки сайта, дисциплины и отдельные коллекции «База знаний» и «Домашние задания».
2. Создать черновики статьи базы знаний и ДЗ, заполнить тексты. Проверить успешную сборку и отсутствие обоих черновиков на сайте.
3. Опубликовать оба материала. После успешного GitHub Actions открыть их прямые ссылки: объяснение и все условия задания должны читаться на страницах без скачивания.
4. Исправить объяснение статьи и текст ДЗ. После следующей сборки проверить обновление текста в соответствующих разделах.
5. Указать ошибочный код раздела или очистить текст опубликованного задания. Проверить отказ проверки контента: опубликованная ранее версия должна оставаться доступной.
6. Удалить тестовые материалы, включая последнюю запись коллекции. Проверить навигацию и два пустых состояния дисциплины.
7. Проверить доступ к редактированию у единственного владельца репозитория и отсутствие возможности редактирования у студента без этих прав.

Unit-тест дополнен явным `blur` перед `resize`, воспроизводящим этот порядок событий; браузерная проверка не ослаблялась.

- Финальный полный прогон: **132 E2E-теста прошли за 1,1 минуты**, без пропусков и падений. Проверены все 12 сочетаний размера экрана и темы.
