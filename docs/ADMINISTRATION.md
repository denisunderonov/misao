# Как редактировать МИСАО

## Первое подключение

1. Сначала загрузите сайт в свой GitHub-репозиторий и включите публикацию через GitHub Actions: инструкция в [PROJECT.md](PROJECT.md).
2. Откройте [app.pagescms.org](https://app.pagescms.org/) и войдите своим GitHub-аккаунтом.
3. Установите GitHub App Pages CMS. Выберите доступ только к репозиторию этого сайта.
4. Откройте репозиторий и ветку `main` в Pages CMS. Файл `.pages.yml` уже включён в проект, создавать его заново не нужно.
5. Вы увидите «Настройки сайта», «Дисциплины и разделы», «База знаний» и «Домашние задания».

Pages CMS бесплатен по [условиям разработчика](https://pagescms.org/). Он редактирует файлы в GitHub через визуальный текстовый редактор. Тексты объяснений и домашних заданий сохраняются в Markdown. Загрузка файлов для этого сайта не настроена: PDF не используются. Вход преподавателя находится в отдельной панели CMS; студенты открывают сайт без входа. При единственном редакторе достаточно вашего GitHub-аккаунта: не приглашайте других редакторов в CMS и не выдавайте им права записи в репозиторий.

Установка приложения и реальный вход проверяются владельцем GitHub-аккаунта после подключения репозитория. Локальные тесты проверяют конфигурацию и файлы, а не авторизацию внешнего сервиса.

## Добавить тему

1. В «Дисциплины и разделы» посмотрите **код дисциплины** и **код раздела**. Например `mathematics` и `algebra`.
2. Если нужного раздела нет, добавьте его в дисциплину, задайте код, название и порядок, затем сохраните.
3. В «База знаний» создайте новую запись. Введите название и краткое описание карточки.
4. Скопируйте коды дисциплины и раздела. Задайте уникальный код темы латиницей, например `quadratic-equations`. Эти коды образуют ссылки, поэтому после публикации их лучше не менять.
5. Укажите порядок и дату обновления. В визуальном редакторе напишите объяснение: заголовки, списки, таблицы и код поддерживаются.
6. Теория хранится отдельно от заданий; весь текст объяснения отображается на странице.
7. Включите «Опубликовать тему» и сохраните.
8. В GitHub → Actions дождитесь зелёного workflow. Он прогонит проверки, соберёт и опубликует сайт. Затем откройте объяснение в разделе «База знаний» дисциплины.

## Добавить домашнее задание

1. В «Домашние задания» создайте запись с названием и кратким описанием карточки.
2. Скопируйте коды дисциплины и раздела так же, как для темы. Задайте код задания, порядок и дату. Код задания может совпадать с кодом темы: у них разные адреса.
3. В поле «Условия задания и дополнительная информация» напишите **все условия задач**. Добавьте требования к оформлению, срок или способ сдачи и критерии оценки. Можно использовать заголовки, нумерованные списки, выделения, таблицы и блоки кода.
4. Включите «Опубликовать задание» и сохраните. После успешного workflow откройте карточку в разделе «Домашние задания»: весь текст должен быть виден на странице без скачивания файлов.

Объяснение и задание можно публиковать, менять и удалять независимо друг от друга.

Если workflow завершился ошибкой, предыдущая успешная версия сайта продолжит работать. В логе ищите `Content validation failed`: чаще всего указан неверный код раздела, повторяется код темы, неверная дата или отсутствует текст задания.

## Изменить объяснение или задание

Откройте запись в «База знаний» или «Домашние задания», измените текст, обновите дату и сохраните. После успешного workflow проверьте страницу материала. Код темы или задания лучше сохранить прежним, чтобы не сломать старые ссылки.

## Добавить дисциплину

В «Дисциплины и разделы» добавьте элемент: код, название, значок, цвет и разделы. Описание дисциплины не требуется: на главной показаны только названия. Новые карточки автоматически занимают следующие строки сетки по две (на узких экранах - по одной). Значки: `calculator`, `code`, `globe`, `database`, `braces`, `book`. Цвета: `blue`, `mint`, `violet`, `peach`. Изменять React-код или `.pages.yml` для новой дисциплины не нужно. Затем создавайте темы, указывая её код.

## Черновики и удаление

Выключенная публикация (`published: false`) скрывает соответствующую тему или задание из сборки. Это позволяет хранить незавершённый текст. При удалении раздела или дисциплины сначала перенесите, снимите с публикации или удалите связанные темы и задания.

GitHub Pages предназначен для общедоступных материалов: скрытая тема не делает файлы публичного репозитория приватными. Не используйте черновик как хранилище закрытых документов.

Начальную тему и задание «Линейные уравнения» можно удалить после проверки сайта или заменить собственными материалами. Тесты публикации не требуют сохранения демонстрационных записей.

## Ссылка в футере

В «Настройки сайта» поле «GitHub для ссылки в футере» содержит `https://github.com/denisunderonov`. При необходимости замените его на URL своего профиля. Подпись остаётся «Дизайн и разработка сайта: Github». Под ней отображается «© 2026».

## Редактировать без CMS

Можно менять Markdown и JSON через GitHub или локальный редактор. Объяснения находятся в `content/topics/`, домашние задания - в `content/assignments/`. Сохраняйте YAML-метаданные в начале записи между двумя строками `---`. Пример задания:

```yaml
---
subject: mathematics
section: algebra
slug: quadratic-equations
title: Квадратные уравнения
order: 2
updatedAt: '2026-11-18'
published: true
---
```

Ниже пишутся все условия в Markdown, например:

```markdown
## Решите уравнения

1. x² − 5x + 6 = 0
2. x² = 16

Покажите ход решения и выполните проверку.
```

Для темы базы знаний используйте такую же структуру метаданных, а ниже напишите объяснение. После сохранения в `main` выполняется тот же workflow. История Git позволяет восстановить прежний текст.
